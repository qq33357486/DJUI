# 场景画板与设备适配验收规程

本文用于验收 DJUI 的「场景画板」：背景图与建筑、地图标记等素材坐标内容在不同屏幕比例下保持同一构图。它不替代页面业务验收。

## 一、设计与素材前提

- 新工程的基础画幅是 9:20（1080 × 2400）；横版 20:9（2400 × 1080）使用页面的 responsive.wide 图层提供独立背景和文案。
- 需要随背景一起缩放的元素放进一个 sceneFrame 容器。容器绑定根下背景节点，artboard 填素材实际画幅。
- 返回、货币、设置、弹窗等屏幕 UI 不放入 sceneFrame，继续以 safe / screen 锚定。
- 横版不能把竖版背景强行裁切当成成品：如构图无法接受，必须提供 20:9 背景，并在宽屏图层切换。
- 每张背景图必须有正确的 appearance.sourceSize；cover/contain 的裁切和 sceneFrame 映射都依赖这个值。

## 二、自动门禁

提交或发布前必须全部通过：

1. editor/frontend 下执行 npx tsc --noEmit。
2. editor/frontend 下执行 npm run build。
3. 执行 node scripts/validate-pages.mjs <星火工程根目录>。
4. 若页面包含 sceneFrame，校验器还会确认：背景引用存在且带图片、画板位于根下、画板填满 image 图帧、画板内未混用 screen/safe/image 锚点。

自动门禁只证明协议、几何约束和构建成立；它不替代实际素材构图和触控体验验收。

## 三、精确几何判定

对于 artboard 中任一素材矩形 (x, y, width, height)，设背景完整图帧为 (fx, fy, fw, fh)、素材画幅为 (aw, ah)，预期屏幕矩形为：

~~~
left   = fx + x * fw / aw
top    = fy + y * fh / ah
width  = width  * fw / aw
height = height * fh / ah
~~~

编辑器预览和 Runtime 的四项结果均应满足绝对误差不超过 1 个逻辑像素。这个判定允许截图取整，不允许只移动画板外框而不缩放内部素材。

回归样例：Project_Movie 的 场景1 / building_slot_1_button 使用 1080 × 1920 素材画幅。

| 画布 | 预期矩形 (x, y, width, height) |
| --- | --- |
| 1080 × 1920 | (252, 286, 393, 319) |
| 1080 × 2400 | (180, 357.5, 491.25, 398.75) |

## 四、人工截图验收

1. 在 DJUI 打开工程，依次选择 9:20、9:16、灵动岛、摄像孔、曲面屏、20:9、平板画像；为每个画像保存一张画布截图。
2. 对每个场景取至少两个显著建筑或标记，按上一节公式记录编辑器中的矩形；确认其与背景中的同一像素位置对齐。
3. 使用编辑器的「适配审计」面板：交互控件不能有 error；warning 必须逐条注明是可接受的视觉覆盖、还是需要调整安全区/素材。
4. 用编辑器的 Runtime 更新和发布流程同步到星火工程；不要手工复制 C# 或页面 JSON。
5. 在星火运行同一组物理尺寸/安全区，按相同页面、相同设备画像截图，并同编辑器截图叠加比对。背景、场景素材、屏幕 UI 三类元素分别确认。
6. 通过条件：场景素材的几何误差不超过 1 逻辑像素；安全区内无触控目标被刘海、孔、手势区或曲面触控区遮挡；横版采用对应的宽屏素材/布局。

若编辑器和 Runtime 不一致，先保留两张原始截图、页面 JSON、物理宽高和安全区 Insets，再按「背景图帧、sceneFrame artboard、anchor/stretch、sourceSize」顺序定位；不要通过任意偏移量补丁掩盖差异。

# wideRatio(宽屏判定阈值)调研结论

> 调研时间:2026-08-17  |  结论:**推荐 1.25(维持现值)**,备选 1.30

## 一、判定语义回顾

Runtime DjuiCanvasV6:物理宽/高 >= wideRatio 才进宽屏层(方向感知,竖屏永不触发)。
阈值唯一作用:决定「横置近方形设备」(折叠屏展开横用)归入基础层还是宽屏层。

(手机 CSS 逻辑分辨率,横向全部 >=1.9)— 手机与桌面都在 1.78+,阈值对它们无影响。

## 三、结论推导

折叠屏最大 1.20  <--空档-->  平板最小 1.33,1.25 落在空档正中

- 空档几何中点 = sqrt(1.20 x 1.33) = 约 1.26
- 1.25 与中点几乎重合,是数据支撑的最优分界
- 含义:折叠屏横用 → 基础层(竖图);iPad/安卓平板 → 宽屏层(横图)

## 四、折叠屏横用的量化提示(供实测决策)

cover 模式下折叠屏(1.16)两种素材的保留率:

| 素材 | 保留内容 | 观感 |
|---|---|---|
| 竖图 9:16 | 高度仅保留约 48% | 主体易残缺 |
| 横图 16:9 | 宽度保留约 65% | 通常更可接受 |

若实测折叠屏横用竖图不可接受,两个选项:
1. 阈值降到约 1.05:折叠屏进宽屏层用横图(保留率升到 65%)
2. 后续增加第三档近方形素材(1600x2000, 4:5)——衔接文档已有预案
